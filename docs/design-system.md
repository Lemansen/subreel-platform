# SubReel — визуальный язык и дизайн-система

Версия 0.1 · 2026-10-20 · Основа этапа 2

## 2.1. Бренд

SubReel объединяет разные форматы историй в одном каталоге и помогает продолжать знакомство с ними. Визуальный характер: выразительный, кинематографичный, тёмный, но спокойный; медиа-обложки остаются главным визуальным содержанием.

- Знак: текстовый wordmark `SubReel`; `Sub` нейтральный, `Reel` акцентный. Пока без отдельного графического символа.
- Образ: «целые вселенные» — карточки и страницы показывают связи между произведениями, а не только поток обложек.
- Тон текстов: короткий, ясный, дружелюбный; интерфейс объясняет, что доступно и что произойдёт после действия.
- Принцип бренда: единый каталог для видео и чтения; доступность конкретного источника всегда показывается отдельно.

## 2.2. Цвет, шрифт и геометрия

Тёмная тема — базовая для веб-MVP. Цвета — именованные токены; в компонентах не вводить новые произвольные значения без обновления этой таблицы.

| Токен | Значение | Использование |
|---|---|---|
| `canvas` | `#09090D` | Главный фон |
| `surface-1` | `#111119` | Панели, шапка, диалоги |
| `surface-2` | `#181821` | Карточки, поля ввода |
| `surface-hover` | `#20202B` | Наведение и выбранная поверхность |
| `text-primary` | `#F4F2FA` | Заголовки и основной текст |
| `text-secondary` | `#AAA7B4` | Описания и подписи |
| `text-muted` | `#85828F` | Подсказки и вспомогательная информация; контраст не ниже 4.69:1 на `surface-2` |
| `border-subtle` | `#292833` | Разделители и контуры |
| `accent` | `#A78BFA` | Ссылки, выбранные состояния, небольшие акценты |
| `accent-strong` | `#7C3AED` | Основная кнопка и активные элементы |
| `accent-secondary` | `#E879F9` | Декоративный градиент, не текст длинных абзацев |
| `success` | `#34D399` | Успех |
| `warning` | `#FBBF24` | Предупреждение и временное ограничение |
| `danger` | `#F87171` | Ошибка и разрушительное действие |

Контраст текста и интерактивных элементов проверяется по WCAG AA перед принятием визуального этапа; цвет не должен быть единственным способом передать статус.

- Основной шрифт: Geist Sans с кириллическим набором; моноширинный Geist Mono — только для кодов, тайм-кодов и технических значений.
- Иерархия: display 48–72 px; заголовок страницы 32–48 px; секция 24–32 px; карточка 16–20 px; основной текст 14–16 px; вспомогательный не меньше 12 px.
- Базовый шаг отступов: 4 px; типовые интервалы 8/12/16/24/32/48 px.
- Скругления: 8 px для полей и небольших меток, 12 px для кнопок, 16 px для карточек, 24 px для крупных панелей.
- Контейнер: максимум 1280 px; контент на мобильном занимает ширину с полями 16–20 px.
- Обложки каталогов используют пропорцию 3:4 и фиксированную область изображения, чтобы сетка не прыгала при загрузке.

## 2.3. Базовые компоненты

| Компонент | Правила |
|---|---|
| `SiteHeader` | Wordmark слева, основные разделы в центре/меню, аккаунт справа; на узком экране навигация сворачивается, основные действия остаются доступны. |
| `PageContainer` | Общая ширина, горизонтальные поля и вертикальный ритм страницы. |
| `Button` | Варианты primary, secondary, quiet и destructive; минимум 44×44 px для основного касания; состояния default/hover/focus/disabled/loading. |
| `TextField` / `SearchField` | Постоянная подпись, понятный placeholder, видимый focus-ring, текст ошибки рядом с полем. |
| `ContentCard` | Обложка, тип, название, необязательный год; доступна как единая ссылка; изображение имеет резервный фон и фиксированную пропорцию. |
| `RelationCard` | Обложка и название связанного тайтла плюс текстовая метка вида связи; различие связи не кодируется только цветом. |
| `FilterChip` | Подписанный фильтр с явным активным состоянием; на мобильном доступен в горизонтальной прокрутке или панели фильтров. |
| `StatusBadge` | Тип контента, статус публикации или доступности источника; семантический цвет сопровождается текстом/иконкой. |
| `ProfileAvatar` | Аватар с текстовым fallback; размер и доступное имя задаются контекстом. |
| `Dialog` / `Drawer` | Dialog для подтверждений; нижний drawer для мобильных фильтров; закрытие клавишей Escape, фокус удерживается внутри. |
| `LoadingState` | Skeleton повторяет конечный размер карточки/секции, не создаёт layout shift. |
| `EmptyState` | Коротко объясняет отсутствие данных и предлагает следующий доступный шаг. |
| `ErrorState` | Нейтрально сообщает о проблеме, не показывает сырые сообщения сервера/провайдера; retry, если операция безопасно повторяема. |

### Доступность и адаптивность
- Все действия работают клавиатурой и имеют заметный `focus-visible` контур.
- Интерактивные цели не меньше 44×44 CSS px для основных мобильных действий.
- Формы связывают label, input и error через семантическую разметку и доступное имя.
- Сетка карточек: 2 колонки на узком мобильном, 3 на среднем экране, 4 на широком; важные действия не прячутся только в hover.
- Пользовательские предпочтения reduced motion соблюдаются; анимация не должна задерживать доступ к содержимому.

### Исходное состояние
Текущие `src/app/page.tsx`, `src/app/globals.css` и `src/app/layout.tsx` уже используют тёмную поверхность, фиолетовый акцент, wordmark и Geist. Эта спецификация нормализует существующее направление; перенос разрозненных цветов в CSS-токены и выделение компонентов выполняются при реализации 2.3.
