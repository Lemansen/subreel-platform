# SubReel — спецификация экранов веб-MVP

Версия 0.1 · 2026-10-20 · Этап 2.4–2.7

Документ фиксирует структуру экранов до расширения реализации. Все экраны используют токены и базовые компоненты из [`design-system.md`](design-system.md), единый `SiteHeader` и опубликованные данные каталога.

## 2.4. Главная

### Структура
1. **Шапка:** wordmark; ссылки «Главная» и «Каталог»; поле/кнопка поиска; справа «Войти» для гостя или меню профиля для вошедшего пользователя.
2. **Первый экран:** короткое описание платформы; основное действие «Открыть каталог»; вторичное действие «Найти историю» фокусирует поиск. Справа на широком экране — подборка/обложки, без критичного текста в изображении.
3. **Продолжить:** только для вошедшего пользователя и только если есть сохранённый прогресс; отдельные строки «Смотреть» и «Читать» показываются при наличии записей.
4. **Новые произведения:** опубликованные тайтлы с датой добавления; ссылка «Весь каталог».
5. **Категории:** быстрые переходы к фильтрам типа контента.
6. **Франшизы и связи:** подборка франшиз/связанных историй показывается, когда такие данные существуют.
7. **Подвал:** краткая информация, правила и ссылки на политику/условия после их подготовки.

### Адаптивность и состояния
- На телефоне один с# SubReel — дорожная карта разработки

Давай разделим весь проект на большие этапы, а каждый этап — на конкретные подэтапы с номерами `1`, `1.1`, `1.2`, `2`, `2.1` и так далее.

Сделаем это как полноценный план разработки продукта: от проектирования и базы данных до сайта, Android-приложения, плеера, читалки, совместного просмотра, административной панели и запуска.

Будем придерживаться трёх принципов:

- Последовательность: каждый следующий этап опирается на уже готовые компоненты.
- Проверяемость: у каждого подэтапа есть конкретный результат и критерии завершения.
- Постепенное развитие: сначала создаём рабочую основу, затем добавляем сложные возможности, не переписывая архитектуру.

Основной стек предлагаю оставить таким: Next.js + TypeScript для сайта, React Native + Expo для Android, Supabase + PostgreSQL для базы данных и авторизации, FastAPI для тех серверных задач, которым он действительно понадобится.

Сайт и приложение будут разными клиентами одной платформы, с общим каталогом, аккаунтами и пользовательскими данными.

- На широком экране hero в две колонки и сетка карточек 3–4 колонки.
- Загрузка: skeleton сохраняет высоту hero и сетки.
- Пустой каталог: объяснение и ссылка в админ-процесс/действие наполнения, доступное редактору.

- Пользователь без прогресса не видит пустой блок «Продолжить».

## 2.5. Каталог и поиск

### Структура
1. Заголовок «Каталог» и количество найденных записей.
2. Поиск по локализованным и оригинальным названиям; отправка формы по Enter, очистка запроса.
3. Фильтры: тип контента; жанры; год/диапазон лет; наличие доступного формата — только после появления соответствующих данных.
4. Сортировка: недавно добавленные, название, год; значение по умолчанию ясно обозначено.
5. Выбранные фильтры отображаются чипами с отдельным удалением и общей кнопкой «Сбросить».
6. Сетка `ContentCard`; пагинация с текущей страницей и понятными «Назад/Дальше».

### Поведение
- URL отражает поисковую строку, фильтры, сортировку и страницу; ссылку на выдачу можно скопировать или обновить без потери состояния.
- Каждый фильтр можно применить клавиатурой; изменение формы не сбрасывает несвязанные активные фильтры.
- На мобильном фильтры открываются в `Drawer`, поиск остаётся над результатами; применение показывает число активных фильтров.
- На десктопе панель фильтров располагается сбоку от выдачи либо компактной строкой над сеткой, если ширины недостаточно.

### Состояния
- Начальная загрузка: skeleton карточек и фильтров.
- Нет совпадений: показать поисковый запрос, предложить очистить часть фильтров.
- Пустая база: объяснить, что каталог ещё наполняется.
- Ошибка: сохранить введённые параметры и предложить повторить загрузку.

## 2.6. Страница франшизы

1. Шапка и breadcrumb «Каталог → Франшизы → название».
2. Обложка/баннер, название и описание франшизы.
3. Список участников франшизы с фильтром по формату и сортировкой по дате/порядку просмотра.
4. Карточка каждого тайтла показывает тип, год и короткую роль/связь в франшизе, если она размечена.
5. Ссылки на соседние тайтлы и их страницы; отсутствие доступного медиа не скрывает запись из каталога.

### Адаптивность и состояния
- На телефоне обложка и описание идут над одной колонкой карточек.
- На широком экране hero располагается в две колонки; список может иметь 2–3 колонки карточек.
- Пустая или неизвестная франшиза даёт страницу 404; ошибка данных не маскируется как пустой список.
- Если обложки нет, используется фоновая заглушка с названием, без растянутого сломанного изображения.

## 2.7. Страница тайтла

### Структура
1. Шапка и breadcrumb с переходом к каталогу и, если есть, франшизе.
2. Обложка; тип, год и статус доступности; название и оригинальное название.
3. Жанры, описание и метаданные.
4. Основное действие зависит от данных: «Смотреть» для доступного видео, «Читать» для доступного чтения, обе кнопки при наличии обоих форматов. Если источника нет, сообщить «Источник пока недоступен».
5. Для видео: выбор сезона и серии; для чтения: издание/том/глава. Блоки не показывать до появления этих сущностей.
6. Связанные произведения с точными подписями направления («Оригинал», «Экранизация», «Продолжение», «Приквел» и т. д.).
7. Блок «Ещё во франшизе» с переходом на страницу франшизы.
8. Вошедший пользователь видит действие добавления в список; его состояние и прогресс доступны только ему.

### Адаптивность и состояния
- На телефоне обложка компактная и располагается над метаданными; основные действия доступны без прокрутки до связанных произведений.
- На десктопе обложка слева, метаданные и действия справа; связанные тайтлы располагаются сеткой.
- Черновик/архивный тайтл для гостя ведёт на 404; неизвестный slug — 404.
- Главные метаданные загружаются вместе; сбой второстепенного блока не скрывает основную карточку, а даёт локальное состояние ошибки.
- `title` и `description` вкладки/поисковой выдачи формируются из имени, типа и описания тайтла.

## 2.8. Видеоплеер

### Структура
1. Компактная шапка: назад к тайтлу, название тайтла, сезон/серия и переход к списку эпизодов.
2. Область воспроизведения с пропорцией 16:9, устойчивым размером до загрузки видео и полноэкранным режимом.
3. При нескольких разрешённых источниках — явный список источников/озвучек; недоступные источники не предлагаются как действующие.
4. Панель управления: play/pause, текущая позиция и длительность, seek-bar, громкость, субтитры, выбор качества и fullscreen. «Следующая серия» показывается только если она существует.
5. Ниже — метаданные эпизода, описание и список серий/сезонов.

### Адаптивность и управление
- На десктопе видеополе занимает центральную широкую колонку; список серий можно разместить справа при достаточной ширине, иначе ниже.
- На телефоне видео остаётся широкоэкранным; шапка компактная, список серий и настройки идут ниже. Кнопки управления рассчитаны на касание, основные элементы имеют доступные подписи.
- Управление клавиатурой: Space/K play-pause (если фокус не в поле ввода), стрелки перематывают/регулируют громкость, M — mute, F — fullscreen; сочетания не перехватываются при вводе текста.
- Автовоспроизведение не запускается со звуком без явного действия пользователя. Синхронизация комнат не входит в этот экран MVP.

### Состояния
- Загрузка: постер/фон и индикатор; размер плеера не меняется после загрузки.
- Источник отсутствует: понятный текст и возврат к странице тайтла; не показывать неработающие контролы.
- Ошибка источника: объяснение без сырого URL или внутренней ошибки, действия «Повторить» и «Выбрать другой источник», если он есть.
- Источник закончился: предложить следующую серию; автоматический переход — только согласно настройке пользователя.
- Ошибка сети: сохранять безопасную текущую позицию локально до повторной отправки; не объявлять сохранение на сервере, пока оно не подтверждено.

## 2.9. Читалка

### Общая структура
1. Верхняя панель: назад к тайтлу, название, текущий том/глава и меню настроек.
2. Поле чтения занимает максимум доступной ширины; фон страницы отделён от элементов управления.
3. Нижняя панель: предыдущая/следующая глава, текущая позиция/номер страницы, индикатор прогресса и список глав.
4. Настройки запоминаются для пользователя и формата; личный прогресс хранится отдельно от общей комнаты.

### Режимы
- **Графическое произведение:** постраничный режим и непрерывная вертикальная прокрутка; направление чтения (слева направо/справа налево); fit-width/fit-height и масштаб.
- **Вертикальный вебтун:** непрерывная прокрутка с корректной подгрузкой длинных изображений; переход к следующей главе доступен внизу.
- **Текст:** размер и гарнитура шрифта, межстрочный интервал, ширина строки/колонки, фон страницы и направление чтения. Настройки не меняют сохранённую позицию.
- Режимы показываются только для формата, который предоставлен доступным источником.

### Адаптивность и управление
- На телефоне контент занимает экран между компактной верхней панелью и управлением; настройки и список глав открываются в нижнем `Drawer`.
- На десктопе панель инструментов располагается сверху или сбоку от области чтения; текстовая колонка ограничена по ширине для удобства чтения.
- Клавиатура: стрелки/кнопки на экране для страниц и глав; жесты на сенсорном экране — дополнительный способ навигации, но не единственный.
- Перелистывание не должно случайно срабатывать при прокрутке или управлении масштабом; всегда доступна явная кнопка предыдущей/следующей страницы.

### Состояния
- Загрузка главы: skeleton/фон соответствует размеру страницы или потока.
- Нет разрешённого источника: текст с объяснением и переходом к странице тайтла.
- Ошибка изображения или страницы: локальная заглушка и возможность повторной загрузки, остальные страницы остаются доступны.
- Последняя страница/глава: явное завершение и переход к следующей главе/тайтлу, если они существуют.
- Сохранение прогресса показывает подтверждённое состояние; при потере сети прогресс ставится в очередь и синхронизируется после восстановления связи.

## 2.10. Профиль и библиотека

### Личный профиль
1. Шапка профиля: аватар с fallback, отображаемое имя, никнейм, краткое описание; email показывается только владельцу.
2. Вкладка/ссылка «Моя библиотека» и настройки аккаунта.
3. Редактирование профиля доступно владельцу; поля валидируются, ошибки показываются рядом с полем, сохранение подтверждается сообщением.
4. Настройки приватности позволяют выбрать видимость публичных полей и активности; личные списки, оценки и прогресс скрыты по умолчанию.
5. Выход из аккаунта и запрос удаления размещаются в настройках; удаление требует повторного подтверждения.

### Публичный профиль
- Показывает только поля, разрешённые настройками владельца; email, скрытые списки и прогресс никогда не выводятся.
- Вошедшему посетителю доступны запрос в друзья и блокировка только при разрешении настройками; владельцу — редактирование, посетителю — действия взаимодействия.
- Неизвестный username и закрытый профиль имеют отдельные состояния; приватность не раскрывает существование скрытых данных.

### Библиотека
- Верхняя строка: «Продолжить», «Смотрю», «Посмотрел», «Читаю», «Прочитал», «Избранное»; пользовательские списки могут добавляться позднее.
- Поиск внутри списка, фильтр по типу контента и сортировка по обновлению/названию.
- Карточка показывает статус и краткий прогресс; переход открывает тайтл или продолжает с сохранённой позиции.
- Пустой список предлагает открыть каталог; при ошибке сохранения не сбрасывает выбор пользователя.
- На мобильном вкладки превращаются в горизонтальные чипы/scrollable navigation; фильтры — в drawer.

## 2.11. Друзья и комнаты

### Друзья и социальные действия
- Разделы: поиск пользователей, входящие заявки, исходящие заявки, друзья и заблокированные пользователи.
- Карточка пользователя показывает только публичную информацию; действия (принять, отклонить, отменить, удалить из друзей, заблокировать) доступны только в соответствующем состоянии.
- Действие блокировки просит подтверждение, объясняет последствия и позволяет отмену через отдельный список.
- Комментарии и реакции отображают автора, дату, контекст тайтла и жалобу; заблокированный автор не инициирует доступ к профилю.

### Совместная комната
- До входа: название/тип сеанса, хост, участники и приглашение; вход только по действующему приглашению.
- Во время сеанса: область просмотра/чтения, список участников, состояние соединения, хост и режим управления.
- Смена хоста или закрытие комнаты объясняются всем участникам; конфликт/устаревшая команда не оставляет экран в неопределённом состоянии.
- После выхода личный прогресс остаётся в библиотеке; повторный вход восстанавливает комнату только пока она активна.
- Для MVP эти экраны не нужны; макеты должны быть изолированы от личной библиотеки и плеера/читалки.

## 2.12. Административная панель

### Структура
1. Отдельная защищённая область с явным названием «Администрирование»; не показывается пользователям без серверно подтверждённой роли.
2. Навигация: обзор, франшизы, тайтлы, связи, источники, пользователи, жалобы, журнал действий — пункты появляются только при наличии соответствующего разрешения.
3. Списки дают поиск, фильтры по статусу/типу, пагинацию и видимую дату последнего изменения.
4. Формы создания/редактирования содержат валидацию, черновое сохранение и предпросмотр опубликованных метаданных.
5. Публикация, архивирование, изменение роли и удаление требуют отдельного подтверждения с кратким описанием последствий.
6. История действий показывает исполнителя, действие, объект, время и результат; секреты и лишние персональные данные не отображаются.

### Состояния и безопасность
- Нет роли/сессии: серверный запрет доступа; скрытие ссылки в меню используется только для удобства, не как проверка доступа.
- Ошибка сохранения: значения формы остаются на месте; сообщение не показывает внутренний SQL/секреты.
- Дубликаты: рядом с совпадением действие сравнения/объединения, опасное объединение требует подтверждения и аудита.
- Пустые списки: объяснение и разрешённое действие создания/импорта.
- Разрушительное действие не предлагается, если роль не имеет на него права; клиент повторно подтверждает результат серверного запроса.
- На мобильном таблицы переходят в карточки с приоритетными полями; критические действия остаются явно подписанными.

## 2.13. Адаптивные варианты

| Ширина viewport | Компоновка |
|---|---|
| 360–639 px — мобильный | Одна колонка; горизонтальные поля 16 px; компактная шапка с отдельной полосой ссылок «Главная»/«Каталог» и доступным поиском; основные цели касания от 44 px; фильтры/настройки в drawer; карточки минимум 2 колонки только если название и действия остаются читаемыми, иначе одна колонка. |
| 640–1023 px — планшет | Контент сохраняет одну основную колонку или переходит в две; фильтры доступны над результатами; карточки 2–3 колонки; вторичные панели не сжимают основной контент. |
| 1024 px и шире — desktop | Контейнер до 1280 px; боковая панель фильтров/эпизодов допускается; сетки 3–4 колонки; hero может использовать две колонки. |

Перестройка не меняет порядок чтения и не скрывает функции; горизонтальная прокрутка применяется только к явно выделенным спискам карточек, а не ко всей странице. Макеты проверяются минимум на 360 px, 768 px и 1280 px, включая длинные локализованные названия и отсутствие изображений.

## Общие критерии приёмки экранов
- Проверить узкий экран 360 px, планшет и широкий desktop без горизонтального overflow.
- Проверить таб-навигацию, видимый focus-ring, доступные имена изображений/кнопок и текстовые статусы.
- Для каждого маршрута вручную пройти успешную загрузку, загрузку, пустой результат и ошибку; проверить 404 для отсутствующей/непубличной записи.
- Ссылки ведут на реализованные маршруты либо имеют явное временное состояние; кнопки не выглядят рабочими, если действие ещё не подключено.

## 2.14. Общие состояния экранов

| Состояние | Правило |
|---|---|
| Первичная загрузка | Skeleton/placeholder совпадает с формой контента и резервирует пространство; кнопки не создают ложное впечатление завершённого действия. |
| Пустой результат | Сообщить, почему данных нет, и предложить следующий доступный шаг (сброс фильтра, открыть каталог, добавить первый элемент). |
| Ошибка сети/сервера | Показать безопасный текст и retry, если запрос можно повторить; не выводить внутренние ошибки и токены; сохранить введённые пользователем значения. |
| Нет контента/источника | Различать «тайтл отсутствует», «источник не добавлен» и «источник временно недоступен»; не показывать активные контролы воспроизведения/чтения. |
| Нет доступа | Сервер отклоняет операцию; интерфейс объясняет требуемое действие без раскрытия скрытых данных. |
| Успешное изменение | Подтвердить сохранение/изменение после ответа сервера; для локального офлайн-сохранения честно показать, что синхронизация ожидается. |
| Не найдено | Для неизвестного/непубличного slug — 404; приватные ресурсы не должны различать отсутствие и запрет так, чтобы раскрыть их существование. |

Состояния для ошибок и пустых данных используют общий `ErrorState`/`EmptyState` из дизайн-системы, но текст остаётся контекстным для текущего действия.

## Сверка с текущей реализацией
- `/`: есть hero и первые восемь новых тайтлов; нет поиска, полноценного каталога, прогресса и персональной шапки.
- `/catalog`: отдельного маршрута нет; фильтры, поиск и пагинация не реализованы.
- `/franchise/[slug]`: маршрута нет.
- `/title/[slug]`: базовая карточка и связи есть; нет доступности источников, сезонов/глав и динамических metadata; по правилу направления связей потребуется уточнить подписи.
